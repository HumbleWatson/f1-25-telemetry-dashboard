# i18n Internationalization — Design Spec (en)

Date: 2026-06-30

## Overview

Add Simplified Chinese (zh-CN) internationalization support to both frontends of Pits n' Giggles. Currently 100% English, zero i18n infrastructure.

## Scope

- **Primary:** `apps/frontend/` (Vanilla JS dashboard, ~220-270 strings)
- **Secondary:** `apps/external/f1-save-viewer/` (React save viewer, ~110-145 strings)
- **Languages:** en (default) + zh-CN
- **Excluded:** Python backend strings, CSS content, pure data values (lap times, driver names, etc.)

## Translation Data

Single JSON file at `apps/frontend/i18n/translations.json`, layered by language then namespace:

```json
{
  "en": {
    "common": { "loading": "Loading...", "na": "N/A", "leader": "Leader" },
    "raceTable": { "pos": "POS", "driver": "DRIVER", "bestLap": "BEST LAP" }
  },
  "zh-CN": {
    "common": { "loading": "加载中...", "na": "无", "leader": "领跑者" },
    "raceTable": { "pos": "名次", "driver": "车手", "bestLap": "最快圈" }
  }
}
```

- Dot-notation keys: `__("raceTable.pos")`
- Supports interpolation: `__("toast.speedChanged", { value: "km/h" })`
- Shared master file. React app maintains per-locale copies at `src/i18n/locales/` extracted from the master during development

## 1. Vanilla JS Dashboard (`apps/frontend/`)

### Architecture

New file `apps/frontend/js/i18n.js`:

```
i18n.js responsibilities:
  - Fetch translations.json at startup
  - Expose global window.__() function
  - Manage current language in localStorage (key: "png_lang")
  - Dispatch i18n:change event on language switch
  - Update document.documentElement.lang
```

### `__(key, params)` Implementation

```js
function __(key, params) {
  const lang = getCurrentLang();
  const value = key.split('.').reduce((o, k) => o?.[k], translations[lang]);
  if (!value) return key;
  return params
    ? value.replace(/\{(\w+)\}/g, (_, k) => params[k] ?? `{${k}}`)
    : value;
}
```

### Language Selection

Add a `<select>` dropdown in the existing Settings modal (driver-view.html). Options: English / 简体中文. On change, save to localStorage, toggle `document.documentElement.lang`, dispatch event.

### Migration Strategy

Replace hardcoded English strings in JS files with `__()` calls, file by file:
1. `app.js` — toasts, status text, click handler labels
2. `utils.js` — `showToast()` messages, formatting labels
3. `raceTableRowPopulator.js` — table headers, cell labels
4. `modals.js`, `driverDataModalPopulator.js`, `raceStatsModalPopulator.js` — modal content
5. Remaining files incrementally

HTML Jinja2 templates remain in English (they contain mostly structural text); JS-injected dynamic text is the priority.

### No-Break Guarantee

- `__()` falls back to the key string if translation is missing
- English is always fully populated as the source of truth
- Language switch is purely client-side, no page reload needed

## 2. React Save Viewer (`apps/external/f1-save-viewer/`)

### Architecture

- Add `i18next` + `react-i18next` as dependencies via pnpm
- Initialize in `src/i18n/i18n.ts`
- Per-locale JSON files at `src/i18n/locales/` (mirrored from master `translations.json`)
- Add `LanguageSwitcher` component in the layout header/sidebar

### Implementation Details

```typescript
// src/i18n/i18n.ts
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';

import en from './translations/en.json';
import zhCN from './translations/zh-CN.json';

i18n.use(initReactI18next).init({
  resources: { en: { translation: en }, 'zh-CN': { translation: zhCN } },
  lng: localStorage.getItem('png_lang') || 'en',
  fallbackLng: 'en',
  interpolation: { escapeValue: false },
});
```

- Components use `useTranslation()` hook
- Shared UI primitives (Button, Badge, etc.) receive translated labels as props (no internal i18n coupling)
- Data-driven analysis strings remain in English (formatted on backend)

## Implementation Order

1. Add `translations.json` with all en strings (baseline)
2. Implement `i18n.js` + language switcher in dashboard
3. Translate and migrate Vanilla JS dashboard strings (file by file)
4. Add i18next to React save viewer + translate
5. Verify: switch language, reload, check all UI surfaces

## Non-Goals

- No backend i18n (backend sends raw data; display formatting is client-side)
- No pluralization rules (not needed at current scale; can be added later)
- No RTL support
- No automatic translation
- No JS module bundler for Vanilla JS part
